# GitCommitScribe (`scribe`)

<a name="english"></a>
## 🇬🇧 English

**GitCommitScribe** is a lightweight, zero-native-dependency **.NET Global CLI Tool** that scans your Git commit history using the **Conventional Commits** specification and generates clean, categorized, ready-to-publish `CHANGELOG.md` files and release notes.

### ✨ Features

- **Automatic Tag Range Detection:** Automatically detects commits between your latest Git tag and `HEAD` when no range is specified.
- **Conventional Commits Categorization:** Groups `feat`, `fix`, `perf`, `refactor`, `docs`, and `BREAKING CHANGE` commits into clean Markdown sections.
- **Auto PR & Commit Linking:** Converts `(#42)` references and commit hashes into clickable GitHub links using your `origin` remote URL.
- **Non-Destructive Prepending:** Prepends new release notes to the top of an existing `CHANGELOG.md` without overwriting previous release history.
- **Cross-Runtime Compatible:** Built on .NET 8 with `Major` roll-forward enabled — runs seamlessly on machines with .NET 8, .NET 9, or .NET 10 installed.

### 📦 Installation

Install globally via the .NET CLI:

```bash
dotnet tool install --global GitCommitScribe
```

Update to the latest version:

```bash
dotnet tool update --global GitCommitScribe
```

### 🚀 Usage

Navigate to any Git repository and run `scribe`:

```bash
# Generate changelog from the latest Git tag to HEAD (writes to CHANGELOG.md)
scribe --version-title v1.0.0

# Preview output in terminal without modifying any files
scribe --dry-run

# Generate notes for a specific tag/commit range
scribe --from v1.0.0 --to v1.1.0 --version-title v1.1.0

# Include non-standard commits (chore, ci, build, etc.)
scribe --version-title v1.2.0 --include-other
```

#### Real-World Scenario: `OrderService`

Suppose you are developing a microservice named **`OrderService`** (previously tagged at `v1.1.0`) and push the following commits:

```bash
cd OrderService

git commit -m "feat(checkout): add multi-currency support for international orders (#104)"
git commit -m "fix(payment): resolve timeout issue during 3D Secure callback (#108)"
git commit -m "perf(db): optimize order history query with composite index"
git commit -m "feat(api)!: switch order status endpoint from int codes to string enums" -m "BREAKING CHANGE: OrderStatus field now returns 'Pending' instead of 0."
```

When you are ready to release `v1.2.0`, run `scribe` inside the `OrderService` folder:

```bash
scribe --version-title v1.2.0
```

**Generated `CHANGELOG.md` in `OrderService`:**

```markdown
# Changelog

All notable changes to this project will be documented in this file.

## [v1.2.0] - 2026-11-21

### ⚠️ Breaking Changes

- **api:** switch order status endpoint from int codes to string enums ([8f4a21c](https://github.com/user/OrderService/commit/8f4a21c))
  - **BREAKING:** OrderStatus field now returns 'Pending' instead of 0.

### ✨ Features

- **checkout:** add multi-currency support for international orders ([#104](https://github.com/user/OrderService/pull/104)) ([3c91e0b](https://github.com/user/OrderService/commit/3c91e0b))

### 🐛 Bug Fixes

- **payment:** resolve timeout issue during 3D Secure callback ([#108](https://github.com/user/OrderService/pull/108)) ([7d12b4a](https://github.com/user/OrderService/commit/7d12b4a))

### ⚡ Performance Improvements

- **db:** optimize order history query with composite index ([5e09f8d](https://github.com/user/OrderService/commit/5e09f8d))

---
> Generated by [GitCommitScribe](https://www.nuget.org/packages/GitCommitScribe)
```

#### CLI Options

| Option | Short | Default | Description |
| :--- | :--- | :--- | :--- |
| `--version-title <VERSION>` | `-v` | `Unreleased` | Release heading title (e.g., `v1.2.0`) |
| `--from <REF>` | `-f` | *Latest Git Tag* | Starting Git tag or commit hash |
| `--to <REF>` | `-t` | `HEAD` | Ending Git reference |
| `--output <FILE>` | `-o` | `CHANGELOG.md` | Output Markdown file path |
| `--include-other` | — | `false` | Include `chore`, `ci`, `build`, and unstructured commits |
| `--dry-run` | — | `false` | Print generated Markdown to console without writing to disk |
| `--help` | `-h` | — | Show help and usage examples |
| `--version` | — | — | Show tool version |

### 🗂️ Commit Mapping Rules

| Commit Prefix | Changelog Section |
| :--- | :--- |
| `feat!:` or `BREAKING CHANGE:` | ⚠️ **Breaking Changes** |
| `feat:` / `feature:` | ✨ **Features** |
| `fix:` / `bugfix:` / `hotfix:` | 🐛 **Bug Fixes** |
| `perf:` | ⚡ **Performance Improvements** |
| `refactor:` | ♻️ **Code Refactoring** |
| `docs:` | 📝 **Documentation** |
| Other (`chore:`, `ci:`, etc.) | 🔧 **Other Changes** *(with `--include-other`)* |

## 🇹🇷 Türkçe

**GitCommitScribe**, Git deposundaki commit geçmişini **Conventional Commits** standardına göre analiz ederek kategorize edilmiş, GitHub PR bağlantıları eklenmiş temiz `CHANGELOG.md` dosyaları ve sürüm notları (release notes) üreten hafif, dış bağımlılıksız bir **.NET Global CLI** aracıdır.

### ✨ Özellikler

- **Otomatik Tag Aralığı Algılama:** Herhangi bir aralık belirtilmediğinde son Git etiketi (tag) ile `HEAD` arasındaki commit'leri otomatik olarak tespit eder.
- **Conventional Commits Kategorizasyonu:** `feat`, `fix`, `perf`, `refactor`, `docs` ve `BREAKING CHANGE` commit'lerini düzenli Markdown başlıkları altında gruplar.
- **Otomatik PR ve Commit Bağlantıları:** Depo `origin` adresini okuyarak `(#42)` formatındaki PR referanslarını ve commit hash'lerini tıklanabilir GitHub bağlantılarına dönüştürür.
- **Mevcut Dosyayı Koruma (Prepend):** Var olan `CHANGELOG.md` dosyasının geçmişini silmeden yeni sürüm notlarını dosyanın en üstüne ekler.
- **Geniş .NET Sürüm Desteği:** .NET 8 üzerinde `Major` roll-forward desteğiyle derlenmiştir; makinesinde .NET 8, .NET 9 veya .NET 10 kurulu olan tüm sistemlerde ek ayar gerektirmeden çalışır.

### 📦 Kurulum

.NET CLI kullanarak global araç olarak kurun:

```bash
dotnet tool install --global GitCommitScribe
```

Son sürüme güncellemek için:

```bash
dotnet tool update --global GitCommitScribe
```

### 🚀 Kullanım

Herhangi bir Git deposunun ana klasörüne girip `scribe` komutunu çalıştırın:

```bash
# Son Git tag'inden HEAD'e kadar olan değişiklikleri CHANGELOG.md dosyasına yazar
scribe --version-title v1.0.0

# Dosyaya yazmadan üretilen Markdown çıktısını terminalde önizler
scribe --dry-run

# Belirli iki tag veya commit aralığı için sürüm notu üretir
scribe --from v1.0.0 --to v1.1.0 --version-title v1.1.0

# Standart dışı commit'leri (chore, ci, build vb.) de listeye dahil eder
scribe --version-title v1.2.0 --include-other
```
